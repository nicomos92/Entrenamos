# 0. Product Design Manifesto

EntrenaMos no fue creada para administrar entrenamientos.

Fue creada para ayudar a los entrenadores a dedicar menos tiempo a organizar información y más tiempo a acompañar personas.

Cada pantalla.

Cada botón.

Cada formulario.

Cada componente.

Cada interacción.

Debe existir únicamente si ayuda al entrenador a trabajar mejor.

El entrenamiento siempre tiene prioridad sobre la administración.

La simplicidad siempre tiene prioridad sobre la cantidad de funciones.

La claridad siempre tiene prioridad sobre la estética.

La confianza siempre tiene prioridad sobre la innovación.

Diseñamos para que el entrenador piense en sus alumnos.

No en la aplicación.

---

# 1. Filosofía del Producto

EntrenaMos no es un software de administración.

Es una herramienta de acompañamiento para entrenadores.

Toda decisión de diseño debe contribuir a disminuir la carga administrativa del entrenador.

No buscamos crear la aplicación con más funcionalidades.

Buscamos crear la aplicación que más ayude en el trabajo diario.

Cada nueva funcionalidad deberá responder una pregunta.

> ¿Esta funcionalidad ayuda al entrenador a entrenar más y administrar menos?

Si la respuesta es NO, la funcionalidad no pertenece al producto.

---

# 2. Principios Inquebrantables

Estos principios tienen prioridad sobre cualquier decisión de diseño, desarrollo o negocio.

## 2.1 El entrenamiento siempre tiene prioridad

Toda funcionalidad debe favorecer el tiempo dedicado al entrenamiento.

Nunca al proceso administrativo.

---

## 2.2 Una pantalla responde una única pregunta

Cada vista debe tener un objetivo claro.

Ejemplos:

Dashboard

¿Qué está pasando hoy?

Alumno

¿Cómo está este alumno?

Rutina

¿Qué debe entrenar?

Agenda

¿Qué debo hacer hoy?

Ejercicio

¿Qué ejercicio estoy buscando?

---

## 2.3 Reducir la carga cognitiva

La aplicación nunca debe mostrar más información de la necesaria.

El usuario debe comprender una pantalla en menos de cinco segundos.

---

## 2.4 Contexto antes que datos

No mostramos números.

Mostramos información útil para tomar decisiones.

Incorrecto

28 alumnos

Correcto

28 alumnos

3 requieren seguimiento

---

## 2.5 La aplicación acompaña al entrenador

EntrenaMos nunca reemplaza el criterio profesional.

Lo potencia.

---

## 2.6 El espacio vacío también comunica

No todo espacio debe ocuparse.

El aire mejora la lectura y disminuye la carga visual.

---

## 2.7 Cada clic debe ahorrar tiempo

Toda interacción debe simplificar una tarea.

Nunca agregar pasos innecesarios.

---

## 2.8 Los colores comunican estados

Los colores no decoran.

Informan.

---

## 2.9 Cada componente tiene un propósito

No existen componentes únicamente estéticos.

Todo componente debe resolver un problema.

---

## 2.10 La simplicidad siempre gana

Ante dos soluciones posibles.

Elegimos la más simple.

---

# 3. Personas

EntrenaMos está diseñada para personas.

No para permisos.

## Administrador

Gestiona organizaciones.

Controla configuraciones generales.

Gestiona entrenadores.

---

## Entrenador

Es el usuario principal del producto.

Toda la experiencia gira alrededor de sus necesidades.

Debe sentir que la aplicación trabaja con él.

No para él.

---

## Alumno

Debe poder acceder rápidamente a su entrenamiento.

No necesita aprender a utilizar la aplicación.

Debe abrirla y comenzar a entrenar.

---

# 4. Objetivos del Diseño

El diseño debe transmitir:

• Confianza

• Organización

• Profesionalismo

• Simplicidad

• Cercanía

• Evolución

Nunca deberá transmitir:

• Estrés

• Complejidad

• Competencia

• Sobrecarga

• Agresividad

---

# 5. Principios UX

Toda pantalla debe cumplir los siguientes principios.

✓ Comprensible en menos de cinco segundos.

✓ Máximo una acción principal.

✓ Máximo tres niveles visuales.

✓ Máximo cuatro indicadores principales por sección.

✓ Priorizar el contenido antes que las acciones.

✓ Navegación consistente.

✓ Aprendizaje prácticamente inmediato.

---

# 6. Filosofía del Dashboard

El Dashboard no existe para mostrar estadísticas.

Existe para responder:

¿Qué está ocurriendo hoy?

Debe contar una historia.

No mostrar números aislados.

El entrenador debe comprender el estado de su jornada apenas ingresa.

---

# 7. Filosofía de Componentes

Los componentes existen para resolver tareas.

Nunca para decorar.

Cada componente deberá documentar:

- Propósito
- Problema que resuelve
- Cuándo utilizarlo
- Cuándo evitarlo
- Estados
- Accesibilidad
- Responsive
- Ejemplos
- Reglas para IA

---

# 8. Filosofía de Evolución

EntrenaMos evolucionará continuamente.

Las nuevas funcionalidades deberán integrarse respetando este documento.

Agregar funciones nunca será un objetivo.

Agregar valor sí.

---

# 9. Regla Fundamental

Antes de diseñar cualquier pantalla, responder siempre la siguiente pregunta.

> ¿Esto ayuda al entrenador a dedicar más tiempo a entrenar personas?

Si la respuesta es afirmativa, el diseño está alineado con EntrenaMos.

Si la respuesta es negativa, debe replantearse la solución.
